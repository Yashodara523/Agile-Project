# 8. Sprint Reviews and Retrospectives

This file contains the **formats** used, plus one blank record per sprint. Fill the records in with your real notes. Do not publish invented outcomes.

## 8.1 Sprint Review Format (60 minutes)

| Minutes | Activity |
|---|---|
| 5 | PM: sprint goal and what was planned |
| 30 | Team demonstrates working software on the test environment (stories only count if Done) |
| 10 | Stakeholder feedback captured as new backlog items |
| 10 | Review backlog, risks and timeline; supervisor input |
| 5 | Confirm next sprint goal |

## 8.2 Retrospective Format (45 minutes)

Technique rotated each sprint to keep it fresh:

| Sprint | Technique | Focus question |
|---|---|---|
| 1 | Start / Stop / Continue | How are we setting up as a team? |
| 2 | Mad / Sad / Glad | How is the hand-off between roles working? |
| 3 | 4Ls (Liked, Learned, Lacked, Longed for) | Are we on track for release quality? |
| 4 | Sailboat (wind, anchors, rocks) plus project lessons learned | What will we carry forward? |

**Rules:** safe space, written input first (silent brainstorming), vote on topics, maximum 3 actions, each with an owner and due date. Actions are reviewed at the start of the next retrospective.

## 8.4 Example of a Well-Formed Retrospective Action (format only)

> *Format example, not a recorded result:* "Design hand-offs arrive too late for developers. **Action:** designer delivers annotated Figma frames at least 3 working days before the sprint starts. **Owner:** UI/UX. **Due:** next sprint planning."

## 8.5 Project Closure Checklist

- [ ] All deliverables accepted by supervisor
- [ ] Final report and demo completed
- [ ] Source code and documents archived in the repository
- [ ] Lessons learned documented
- [ ] Open defects and future work handed over (product roadmap ideas)
- [ ] Team recognition and closing meeting held
